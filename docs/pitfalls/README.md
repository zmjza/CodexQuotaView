# QuotaView 长期避坑知识库

## 用途

本目录记录已有证据支持、可复现或可验证的工程教训，用于防止后续
Codex/AI 在开发、修复、测试、部署和排障中重复已知错误。它不取代
`AGENTS.md`、当前规格、`HANDOFF.md` 或版本历史。
现状探测未发现可复用的 pitfalls、troubleshooting、known-issues 或
lessons-learned 等专用目录，因此新建 `docs/pitfalls/` 作为唯一长期入口。

## 读取规则

1. 任何任务开始前先读项目根目录 `AGENTS.md`。
2. 再读本文件，然后读取与任务相关的分类文件。
3. 任务横跨多个模块时，读取所有相关分类，不得只读其中一个。
4. 本知识库只记录避坑证据；当前产品事实仍以生产代码和项目规格为准。

## 写入规则

- 本次历史回填为一次性基线；后续只做增量追加或基于新证据的修正。
- 只写入来自 Git 提交与 diff、项目文档、实际验证或当前对话的可核实事实。
- 信息不足时标注“信息不全，待人工补充”或“以下为基于现有证据的推测”。
- 不记录密钥、Token、账号密码、隐私数据、完整生产配置或完整敏感日志。
- 新坑在当次任务收尾前写回；中断任务尽量先记录已有证据和未完成项。
- 已被新证据否定的内容应就地更正并说明依据，不能用无来由的新结论覆盖。

## 条目格式

每条坑使用 Markdown 二级标题，并包含以下字段：

```markdown
## 简短、可检索的标题

**现象：**

**根因：**

**正确做法：**

**验证方式：**

**禁止事项：**

**相关文件或命令：**

**适用范围：**
```
