# CodexQuotaView 架构文档

## 总体结构

```text
Codex local source
  ├─ macOS Swift CodexAppServerClient ─┐
  └─ Windows Native/WSL Backend ──────┤
                                      v
                         Shared protocol semantics
                  JSON Schema + Fixture + state mapping
                         /                         \
                macOS projection              Windows projection
             SwiftUI/AppKit/Metal        WinUI 3/C#/D3D11/HLSL
```

共享层只共享可审查的协议资产，不引入跨语言 FFI。Swift 和 C# 分别实现解析、状态投影和平台集成；跨平台 Fixture 测试证明结果一致。

## 现有 macOS 模块映射

| 责任 | 当前实现 | 迁移策略 |
|---|---|---|
| Codex 数据读取 | `Sources/QuotaViewCore/CodexAppServerClient.swift` | 保留真实调用链并迁移品牌身份 |
| 领域模型 | `DomainModels.swift`、`CodexProviderAdapter.swift` | 作为共享 Schema 的语义母版 |
| 刷新协调 | `RefreshCoordinator.swift`、`CodexStatusStore.swift` | 保留多消费者协调 |
| 主面板 | `QuotaViewFigmaMenu.swift`、`MenuBarPanelController.swift` | 作为双平台视觉母版 |
| 设置 | `SettingsView.swift`、`AppPreferences.swift` | 保持原生控件和设置语义 |
| Widget | `QuotaViewWidget*`、`WidgetSnapshot.swift` | 更换 App Group/身份并保留安全共享 |
| Activity | `CodexActivityRuntime.swift`、`CodexActivityIsland.swift` | 只迁移稳定单任务状态 |
| Hook | `QuotaViewActivityHook/main.swift` | 更新身份并维持隐私白名单 |
| 更新 | `AppUpdateController.swift`、Sparkle、appcast 脚本 | 建立新 Feed 和密钥治理 |
| 打包 | Xcode、xcconfig、`build-app.sh` | 迁移目标名、版本、签名和产物名 |

## Windows 目标结构

```text
Windows/
  CodexQuotaView.sln
  src/CodexQuotaView.App/          WinUI 3 Shell、托盘、设置、Widget Host
  src/CodexQuotaView.Core/         领域模型、投影、刷新、Native/WSL Backend
  src/CodexQuotaView.Protocol/     共享 Schema 生成/验证入口
  src/CodexQuotaView.Rendering/    C++/WinRT、D3D11、HLSL
  src/CodexQuotaView.Hook/         Named Pipe 与有界文件队列
  tests/...                         单元、Fixture、渲染和烟雾测试
```

最终目录名可在实施时按 Windows App SDK 模板微调，但职责边界、测试入口和禁止项不得改变。

## 数据链路

1. 后端定位本地 Codex 可执行程序。
2. 启动官方本地 `app-server`，调用只读额度和用量方法。
3. 将响应解码为平台原始 DTO。
4. 通过共同 Schema 语义投影为套餐、窗口、余额、Token、健康和可用性状态。
5. 刷新协调器向菜单/托盘、面板和 Widget 发布同一快照。
6. 错误只保留脱敏摘要；无有效快照时显示不可用，不伪造零值。

Windows Native Backend 的具体启动方式必须根据真实 Codex Windows 能力验证；无法原生运行时才选择 WSL 后端。两者都不得读取或复制登录凭据。

## Hook 架构

- 允许字段：Session/Turn Hash、工作区末级名称、事件类型、工具类别、会话来源、时间戳。
- macOS 复用现有本地桥接与 Helper；Windows 使用 Named Pipe，异常时使用容量受限、过期可清理的本地文件队列。
- Schema 默认拒绝未知敏感字段，日志不输出原始载荷。

## Widget 决策

- macOS：WidgetKit Small/Medium，主 App 通过团队前缀 App Group 写快照。
- Windows：先建立正式 API/分发条件的可行性 Spike。只有 Provider 能在目标 Windows 版本、GitHub 直分发和本地数据约束下稳定工作时才采用；否则交付 Compact Widget Host。
- 两种 Windows 路线使用相同 Widget ViewModel 和视觉验收，不允许用“API 不可用”取消首版 Widget 体验。

## 渲染架构

- macOS 26：`NSGlassEffectView` + AppKit 合成；macOS 14–15：`NSVisualEffectView` 回退；流体球使用 Metal。
- Windows：Mica/Acrylic/Backdrop、Windows Composition、DirectComposition/Direct2D 建立基础表面，D3D11/HLSL 实现折射近似和流体球。
- 共享视觉 Token 记录尺寸、间距、色值、透明度、圆角、阴影、字体、状态和动画时间点；平台层允许实现路径不同，不允许视觉结果自由发挥。

## 更新与发布

- macOS：Sparkle 2.9.2 或经验证的兼容版本，新 Bundle ID、新 Feed、新 EdDSA 身份；公开 appcast 仍需产品所有者对精确版本显式准入。
- Windows：Velopack 管理 Setup 和更新通道；Portable ZIP 不伪装成可自动更新安装。
- GitHub Actions 是唯一远端流水线；不包含 Gitee。

## 外部前置

- 新 Apple Developer Team ID 或确认继续使用的合法 Team。
- Developer ID Application 证书和 Notary 凭据。
- 独立 Sparkle EdDSA 密钥及安全备份。
- Windows 代码签名证书。
- 对应 GitHub Actions Secrets。

缺少前置不阻止本地开发和内部构建，但阻止“正式签名、无警告公开分发”收口。
